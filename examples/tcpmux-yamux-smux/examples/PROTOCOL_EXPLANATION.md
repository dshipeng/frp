# TCPMux 流上的协议层次说明

## 当前实现（第5步中的协议）

当服务端在 TCPMux 会话上主动打开新流时，数据包的协议层次如下：

### 1. 底层传输层
- **TCP 连接**：客户端和服务端之间建立的 TCP 连接
- **TCPMux 协议**：在 TCP 连接上建立多路复用会话（yamux 或 smux）
- **逻辑流（Stream）**：在 TCPMux 会话上打开的逻辑流

### 2. 控制协议（当前实现：自定义文本协议）

服务端在流上首先发送的是**自定义的简单文本协议**，用于告诉客户端目标地址：

```
格式：host:port\n
示例：www.example.com:443\n
```

**这不是标准的代理协议**（如 SOCKS5 或 HTTP），而是一个简单的自定义协议。

### 3. 数据转发层

发送完目标地址后，服务端和客户端之间直接进行**双向数据转发**（`io.Copy`），转发的是：
- 用户与目标站点的实际数据
- 可能是 HTTP、HTTPS、TCP 等任意协议的数据

## 协议层次图

```
┌─────────────────────────────────────────┐
│  用户应用数据（HTTP/HTTPS/TCP等）        │
├─────────────────────────────────────────┤
│  自定义控制协议（host:port\n）           │  ← 当前实现
├─────────────────────────────────────────┤
│  TCPMux 逻辑流（Stream）                 │
├─────────────────────────────────────────┤
│  TCPMux 协议（yamux/smux）               │
├─────────────────────────────────────────┤
│  TCP 连接                                │
└─────────────────────────────────────────┘
```

## 改进方案：使用标准代理协议

### 方案1：使用 SOCKS5 协议

在 TCPMux 流上使用标准的 SOCKS5 协议，而不是自定义文本协议：

```
┌─────────────────────────────────────────┐
│  用户应用数据（HTTP/HTTPS/TCP等）        │
├─────────────────────────────────────────┤
│  SOCKS5 协议（标准协议）                  │  ← 改进方案
├─────────────────────────────────────────┤
│  TCPMux 逻辑流（Stream）                 │
├─────────────────────────────────────────┤
│  TCPMux 协议（yamux/smux）               │
├─────────────────────────────────────────┤
│  TCP 连接                                │
└─────────────────────────────────────────┘
```

**SOCKS5 请求格式**：
```
+----+-----+-------+------+----------+----------+
|VER | CMD |  RSV  | ATYP | DST.ADDR | DST.PORT |
+----+-----+-------+------+----------+----------+
| 1  |  1  | X'00' |  1   | Variable |    2     |
+----+-----+-------+------+----------+----------+
```

### 方案2：使用 HTTP CONNECT 协议

在 TCPMux 流上使用 HTTP CONNECT 方法：

```
CONNECT www.example.com:443 HTTP/1.1
Host: www.example.com:443

[之后是原始数据]
```

## 当前实现 vs 标准协议

| 特性 | 当前实现（自定义文本） | SOCKS5 | HTTP CONNECT |
|------|---------------------|--------|--------------|
| 协议标准性 | ❌ 自定义 | ✅ 标准 | ✅ 标准 |
| 支持 IPv6 | ✅ | ✅ | ✅ |
| 支持域名 | ✅ | ✅ | ✅ |
| 错误处理 | ❌ 简单 | ✅ 完善 | ✅ 完善 |
| 扩展性 | ❌ 有限 | ✅ 良好 | ✅ 良好 |
| 实现复杂度 | ✅ 简单 | ⚠️ 中等 | ⚠️ 中等 |

## 总结

**回答您的问题**：

1. **第5步中服务端在会话上主动打开新流时，发送的数据包不是标准的代理协议**（如 SOCKS5 或 HTTP）
2. **而是使用了一个自定义的简单文本协议**：`host:port\n`
3. **之后才是真正的代理数据转发**（HTTP/HTTPS/TCP 等）

如果需要使用标准协议，可以：
- 使用 `socks5_protocol.go` 中的 SOCKS5 实现
- 或者修改为使用 HTTP CONNECT 协议
